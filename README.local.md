# 比稿 · Collate（本地安装）

此目录是当前 JARDIN vault 中安装的插件目录，插件 ID 为 `bigao`。

## 本地验证

在此目录运行：

```text
npm run verify
```

这会检查已安装 `main.js` 的语法、严格检查 `src/` 的 TypeScript 类型、运行已安装 bundle 和纯逻辑回归，然后把恢复中的源码构建到 `dist/main.js` 与 `dist/inline-diff-runtime-v9.js` 并运行 Obsidian API 替身测试。两套 bundle 都覆盖异步比较竞态：新稿件或新渲染开始后，较早的文件读取不能覆盖最新结果。`dist/` 是隔离验证产物，不会自动覆盖当前安装文件；依赖由 `package-lock.json` 固定。

两种对照入口共用同一个可取消的选择器：只列其他 Markdown 笔记，支持按名称或路径搜索、显示所在目录，并将列表限制为最近的 60 项；取消会正常结束操作。这样不会把 PDF、图片等附件误作文本稿件。分屏入口使用 Obsidian 原生 API，可选择左右或上下布局：当前原稿保持在原窗格，选中的对照稿作为普通 Markdown 笔记打开在另一窗格。编辑视图中，两侧都会按词高亮各自独有的文字，并以细边提示删减；差异随未保存编辑短暂防抖刷新，不改写笔记正文。隔离构建中的 `dist/inline-diff-runtime-v9.js` 是当前安装版 `main.js` 的配套运行文件，安装时必须放在同一插件目录。行内标记在编辑器表层绘制，只读取可见文本位置，不修改笔记内容。对比两篇/对比并合并命令仍使用插件差异视图，并读取已打开笔记中尚未保存的编辑内容；输入后会短暂防抖再刷新差异。原生分屏行内高亮最多计算 4,000 行，超限时高亮会保持为空。通过命令面板运行「比稿：关闭分屏对照」可关闭插件创建且仍显示该对照稿的窗格；如果已把窗格改作他用，该命令不会关闭它，也不会关闭旧版比稿面板。追踪会跨插件热重载保留。

## 维护状态

若此前失败的 CodeMirror 扩展注册已残留在工作区，单独重载比稿插件并不能清除这些残留，甚至会让任何新 Markdown 窗格都无法加载。确认编辑内容已保存后，重载整个 Obsidian 工作区可清除残留；当前运行文件不再注册 CodeMirror 扩展。2026-10-17 已在实际工作区清除残留，并验证左右、上下分屏及两篇原文内的差异高亮，插件热重载后追踪与高亮仍正常。覆盖层底色放在正文下方，避免遮淡字色；这些操作没有改动两篇笔记内容。

没有找回本地 `1.2.2` bundle 的原始 TypeScript 工程。`src/` 以 `friebetill/obsidian-file-diff` 的 `1.1.2` tag（commit `d566ded402f72e1508f33b640d6f96d7c32c9a00`）为上游基线恢复，并移植本地分屏、选择器、光标跟随、中文分词、配色及有界差异算法。2026-10-17 已完成核心行为对照：109 组样例下的分词、差异范围、全文显示，全部命令和配色、八种合并动作及同步冲突匹配均与当前安装版一致；源码重复构建产物相同，且未打入独立 CodeMirror 运行时。

源码候选包和冻结安装包均已在 Obsidian 1.14.4 的独立临时测试库运行，验证左右/上下分屏、双侧高亮、编辑刷新、插件重载、全文差异和取消风险提示。报告及人工样例截图在 `dist/`，不提交私人素材。现用运行文件保持不变；这不是所有主题、平台和边界情况完全等价的结论。`npm run package:candidate` 可生成带文件校验记录的完整源码候选包，但没有自动覆盖安装步骤。

bundle 还保留了上游模块边界注释（如 `src/main.ts`、`src/components/differences_view.ts`、`src/data/file_differences.ts`），可用于逐模块恢复；侧栏算法、视图和比较稿选择器是额外的本地代码，恢复时必须一并保留。

`npm run verify` 现包含“严格类型检查 → 已安装包与纯逻辑测试 → 隔离构建 → 源码 bundle 冒烟 → 双版本行为与重复构建检查”。`npm run test:obsidian` 是需显式提供 Obsidian 路径的独立桌面验证，不操作真实 JARDIN 稿件。后续安装候选版仍需明确安排，并保留冻结安装包以便回退。
